# 검사 엔진 (기술 B 기준 구현) · v0.3

공통 레이어 데이터(`docs/layer-data.md`)를 받아 **목적에 따라 다르게 판정하고, 다르게 고치는 방법**을 돌려줘요.
포토샵 없이 동작하는 순수 JS예요. B 담당자가 이어받아 기준과 문구를 다듬는 것을 전제로 만든 **기준 구현**이에요.

```js
const result = Engine.checkDocument(layerData, { medium: "wall", distanceM: 2, lighting: "normal" });
const fixes = Engine.toApplyFixes(result);       // → A의 applyFixes(psd, fixes) 에 그대로
```

| 파일 | 하는 일 |
| --- | --- |
| `engine/policies.js` | ★ **목적별 정책 표** — 기준값·문구. 기획 A가 확정할 곳 (지금은 임시값) |
| `engine/engine.js` | 검사 본체: 크기·대비·굵기·간격·확대 후 배치·위계, 목적 추천, 수정 전략, 충돌 감지 |
| `engine/color.js` | 대비 계산, OKLCH로 '같은 색상·밝기만 조절' 추천색 찾기 |
| `engine/roles.js` | 역할 분류(제목·일시·장소·가격·접근성), 대체텍스트 초안 |
| `test/engine.test.js`, `test/criteria.test.js` | 샘플 포스터로 확인하는 테스트 |

## 목적별 정책 (팀 정책 표 → 코드)

| 목적 | 판정 | 수정 제안 | 추가 지원 |
| --- | --- | --- | --- |
| **예술적 표현** `art` | 기준 미달이어도 **참고** | 밝기 변화 OKLCH 0.12 이내, 크기 수정 없음, 옅은 배경 띠(45%까지). '모두 적용' 없음 | 대체 정보(대체텍스트) 제안 |
| **정보 전달** `info` | 엄격 (**어두운 조명이면 7:1**) | 기준을 넘을 때까지: 밝기 조절 → 배경 띠(90%까지) → 크기 키우기 | 접근성 버전 만들기 추천 |
| **복합** `mixed` | 레이어마다 art / info | 예술 요소는 건드리지 않음. **그림 위 정보 글자에 배경 띠 금지** | 고쳐도 기준 미달이면 **충돌** + 대체 정보 |

레이어 목적은 ① 디자이너가 PSD에 저장한 값 → ② 문서 목적(복합이 아니면) → ③ 엔진 추천값 순서로 정해요.

## 누가 보나요 (보는 사람의 시력) — v0.3

`checkDocument(doc, { viewer: "general" | "low" | "disability" | "severe" })`

| 값 | 시력 (좋은 눈, 교정) | 근거 |
| --- | --- | --- |
| `general` | 1.0 | 기존 기준 |
| `low` | 0.3 | WHO ICD-11: 0.3(6/18)보다 나쁘면 중등도 시각손상 |
| `disability` | 0.2 | 한국 장애정도판정기준(보건복지부 고시): 좋은 눈 0.2 이하 = 시각장애(심하지 않은 장애) |
| `severe` | 0.06 | 같은 기준: 좋은 눈 0.06 이하 = 심한 장애 |

저시력을 고르면 (`policies.lowVisionReading`)
- **글자 크기:** 겨우 보이는 크기 = 5′ ÷ 시력, 통과 = 그 **2배** (저시력 읽기 연구의 고정 여유값 acuity reserve 0.3 log ≈ 2:1). 2m 벽 포스터의 일시 글자: 일반 31pt → 0.3 69pt → 0.2 104pt
- **대비:** 정보 글자 **7:1**, 큰 글자 4.5:1 (WCAG 1.4.6 AAA, 시력 약 0.25 수준의 대비 감도 손실 보완)
- **너무 큰 글자:** 필요한 글자 높이가 포스터 높이의 8%를 넘으면 글자 키우기 대신 **큰 글씨 안내문**을 권해요 (`alternative.type: "largePrint"`, `summary.largePrintRecommended`)

## 검사 항목

### 글자 크기 (`size`)
관람 거리에서 **글자 높이가 눈에 보이는 각도**(분각 ′)로 판정해요. 거리와 상관없이 같은 기준을 쓸 수 있어서예요.
- 글자 높이 ≈ 글꼴 크기 × 0.8 (한글·대문자 근사)
- 통과 ≥ 15′, 주의 ≥ 10′, 실패 < 10′ (시력 1.0이 겨우 읽는 글자 ≈ 5′)
- 통과에 필요한 **추천 pt**를 알려줘요
- **역할별 기준:** 주최·후원·저작권 같은 '그 외' 글자(`secondaryRoles`)는 10′ 이상이면 통과, 못 미치면 **참고** (자동 '모두 추가'에는 안 들어가고 하나씩 추가는 돼요)
- **저시력(0.3):** 기본은 통과한 글자에 '참고'로만 적어요 (`lowVisionRequired: false`). `true`로 바꾸면 통과 기준과 추천 크기가 저시력 기준(약 16.7′)까지 올라가요
- SNS는 휴대폰 화면(너비 65mm, 35cm 거리)에 보이는 크기로 계산해요

| 매체 | 기본 관람 거리 | 2m 벽 포스터 기준 통과 크기 |
| --- | --- | --- |
| 벽 포스터 | 2m | 약 31pt |
| 전단 | 40cm | 약 6.5pt |

### 대비 (`contrast`)
- WCAG 1.4.3: 일반 4.5:1, 큰 글자(18pt 이상, 굵으면 14pt 이상) 3:1
- **이미지 배경 포함:** 배경 픽셀 샘플 하나하나와 대비를 구해서, 가장 낮은 쪽(아주 드문 얼룩 2%는 제외)으로 판정
- 반투명 글자는 배경과 섞은 색으로 계산
- **글자색이 여러 가지면**(강조색 등) 색마다 계산하고 가장 낮은 색으로 판정해요. 수정은 **기준에 못 미치는 색만** 바꿔요 (`fix.runs`)
- 배경 복잡도: 밝기 편차로 단순 / 약간 복잡 / 복잡한 그림 배경

### 시야가 좁은 사람: 핵심 정보 모으기 (`field`) — 근접성의 원칙
- `checkDocument(doc, { field: "normal" | "narrow" | "veryNarrow" })`
- 장애정도 판정기준(보건복지부 고시 제2025-228호): 두 눈의 시야가 각각 모든 방향에서 **10° 이하 = 시각장애(심하지 않은 장애)**, **5° 이하 = 심한 장애**
- 관람 거리에서 한 번에 보이는 지름 = 2 × 거리 × tan(시야각). 2m·10° ≈ 71cm, 40cm·5° ≈ 7cm
- 일시·장소·가격·접근성 글자를 그 지름 안에 몇 묶음으로 나눠 봐야 하는지 셉니다. 1묶음 통과, 2묶음 주의, 3묶음 이상 실패 (예술 문서는 참고)
- `detail.clusters`(묶음 상자), `detail.viewPx`로 화면에서 '한 번에 보이는 범위' 원을 그릴 수 있어요
- **자동 수정 (`fix.type: "infoStrip"`, 글자 하나가 아닌 수정이라 `layerId` 없음)**: 일시 → 장소 → 가격 → 접근성 순서로 글을 모아, 한 번에 보이는 지름의 90% 안에 들어가게 줄을 나눈 **핵심 정보 띠**(검은 글자 + 흰 판). 자리는 일시가 있는 묶음 바로 아래(모자라면 위), 크기는 핵심 정보 중 가장 큰 글자. 기준값은 `visualField.strip`(임시값)
- 이미 핵심 정보를 모두 담은 글자 레이어(핵심 정보 띠 등)가 있으면 한눈에 보인다고 봐요 (`pass`)
- 대체: `alternative.type: "largePrint"` — 큰 글씨 안내문에도 핵심 정보를 모아 함께 붙이기

### 색 의존 정보 (`colorOnly`) — WCAG 1.4.1 색 사용
- 한 글자 레이어 안에서 크기·굵기·기울임·밑줄은 같고 **색만 다른 구간**(레이어 데이터 v0.5 `styleRuns`)을 찾아요
- 그 두 색을 적·녹·청색맹으로 보았을 때(Machado 2009 행렬, `color.simulateCvd`) OKLab 거리가 0.08보다 작으면 **주의**, 여전히 구분되면 **참고**
- 고치기: 굵게·밑줄·기호·괄호처럼 모양으로도 구분하는 게 가장 좋아요
- **자동 수정 (`fix.type: "emphasis"`, `strategy: "shape"`)**: 두 구간 중 짧은 쪽(보통 강조)을 **굵게 + 밑줄**로 — 색을 전혀 못 느껴도 모양으로 구분돼요. 그 색의 **밝기만** 바꿔(색상은 그대로) 구분이 안 되던 색각이상 눈으로도 두 색 거리 ≥ `colorVision.fixDeltaE`(0.12, 임시값)이고 배경 대비 기준을 지킬 수 있으면 `runs[0].value`로 함께 넣어요
- 대비 수정(`color`)과 다른 종류라 같은 레이어에 함께 들어가요
- 한계: 글자 레이어 사이(예: 빨간 '매진' 레이어 vs 파란 '예매 가능' 레이어)나 도형·아이콘의 색 구분은 아직 보지 않아요

### 색각이상일 때 대비 (`cvd`)
- 일반 눈으로는 대비가 **통과**한 글자를, 글자색과 배경 픽셀을 모두 색각이상으로 바꿔 다시 계산해요
- 기준 밑으로 떨어지면 **주의** (예: 검은 바탕 빨간 글자 — 일반 5.3:1, 적색맹 약 1.9:1)
- **자동 수정 (`fix.type: "color"`, `strategy: "cvd"`)**: 일반 눈 대비 목표를 `fixStep`(0.5)씩 올려 가며(최대 `fixMaxContrast` 15) 밝기만 바꾼 색을 찾고, 적·녹·청색맹 세 눈 모두에서 기준을 넘으면 그 색을 써요. `contrastAfter`는 세 눈 중 가장 낮은 대비

### 색각이상 검사 켜고 끄기
- `checkDocument(doc, { colorVision: false })` 이면 `colorOnly`·`cvd`를 하지 않아요 (기본은 켜짐). `result.environment.colorVision`에 남아요

### 글꼴 가독성 (`font`) — 기준 ① 보강
- 글꼴 이름으로 **장식·손글씨 글꼴**(script, brush, 붓, 손글씨, 캘리…), **폭이 좁은 글꼴**(condensed, narrow…), **기울임**(italic, 가짜 기울임)을 찾아요. 영문 키워드는 이름 속 단어의 시작과 비교해요 (OpenSans 의 "pen" 같은 오탐 방지)
- **영문 전부 대문자**(6글자 이상 또는 PSD 대문자 설정)
- 정보 글자는 주의, 예술 글자는 참고. 자동 수정은 없고 글꼴 바꾸기를 안내해요

### 글자 굵기 (`weight`) — 기준 ① 텍스트 가독성
- 글꼴 이름이 Thin·Light·ExtraLight 등이면 **얇은 글씨**로 봐요 (`font.weightGuess`)
- 36pt 이상이면 통과 (큰 제목에 얇은 글꼴은 흔해요). 그보다 작으면 정보 글자는 **주의** + 굵게(`weight`) 제안, 예술 글자는 **참고**
- 보통 굵기 글자는 결과를 만들지 않아요

### 텍스트 간격 (`spacing`) — 기준 ④ (WCAG 1.4.12)
- **여러 줄** 글자의 줄 간격이 글자 크기의 1.5배 미만이면 주의 → `lineHeight: 1.5` 제안
- 자간이 0보다 좁으면(음수) 주의 → `letterSpacingEm: 0` 제안
- WCAG 1.4.12는 원래 "사용자가 간격을 늘려도 깨지지 않아야 한다"는 **웹 기준**이에요. 자간 0.12em·단어 간격 0.16em은 사용자 조정값이라 포스터 기본 기준으로 쓰지 않고 결과 `detail.wcag`에만 적어 둬요
- 한 줄이고 자간이 괜찮으면 결과를 만들지 않아요

### 확대 후 잘림·겹침 (`layout`) — 기준 ③ 텍스트 확대 및 재배치
- 크기 수정 제안이 있으면, **모든 크기 수정을 함께 적용했을 때** 글자 상자가 포스터 밖으로 나가거나 다른 글자와 겹치는지 계산해요 (글자 기준점 중심으로 커지는 것까지 A와 같은 방식)
- 문제가 있으면 **주의** + 겹치는 글자·나가는 방향·**겹치지 않는 최대 크기**(`maxFitPt`)를 알려줘요. 크기 결과의 `fix.layoutWarning`에도 적어요
- 크기 수정이 없는 글자도 **지금 이미** 겹치거나 잘려 있으면 알려줘요
- 자동 재배치(줄바꿈·위치 이동)는 하지 않아요. 디자이너 판단이 필요해서예요

### 정보 계층 (`hierarchy`) — 기준 ⑤ 정보 계층 및 그룹화
- 제목·일시·장소가 없으면 **누락**
- 일시·장소가 전체 글자 중 작은 편(중간값 미만)이면 **주의**. 크기 순위는 같은 크기가 여럿이면 '공동 n위'로 보여줘요
- **제목과 본문 구별:** 제목이 나머지 글자 중간 크기의 1.5배 미만이면 주의
- **관련 정보 근접:** 일시–장소 사이 거리가 포스터 높이의 12%보다 멀면 주의 (`relatedPairs`로 쌍 추가 가능)
- **밀집:** 위아래로 놓인 글자 묶음 사이가 글자 크기의 0.3배보다 좁으면 주의. 글자 상자 면적이 포스터의 40%를 넘으면 주의
- 예술 문서에서는 모두 **참고**

## 정보 전달 지도 (`result.priority`) — 검토 우선순위
실제 사람의 시선을 잰 히트맵이 아니라, **글자 크기 · 대비 · 위치 · 정보 중요도**를 조합해서 "어디부터 검토할지"를 정하는 지도예요. 판정(통과·실패)과는 따로예요.

- **중요도**(역할): 일시·장소 1.0, 제목·접근성 0.9, 가격 0.8, 그 외 0.3 (`policies.priorityMap.importance`)
- **식별 쉬움** = min(크기 점수, 대비 점수) × 위치 점수
  - 크기 점수 = 보이는 각도 ÷ 통과 기준 (0~1), 대비 점수 = (대비 − 1) ÷ (기준 − 1) (0~1)
  - 위치: 포스터 가장자리 6% 안에 붙은 글자는 × 0.8
- **우선순위** = 중요도 × (1 − 식별 쉬움). 0.5 이상 높음, 0.25 이상 중간, 그 아래 낮음
- 보는 사람(저시력)·관람 거리를 바꾸면 크기·대비 점수가 바뀌어서 지도도 바뀌어요

```json
{ "layerId": 6, "role": "date", "importance": 1, "legibility": 0.45,
  "parts": { "size": 0.45, "contrast": 0.63, "position": 1, "atEdge": false },
  "weakest": "size", "score": 0.55, "level": "high", "bounds": { ... } }
```

## 결과 형식

```json
{
  "document": { "purpose": "mixed", "purposeSource": "suggested", "purposeSuggested": "mixed" },
  "environment": { "medium": "wall", "distanceM": 2, "lighting": "normal" },
  "summary": { "counts": { "conflict": 1, "fail": 6, "warn": 5, "advisory": 2, "pass": 5 },
               "applyAllAllowed": true, "accessibleVersionRecommended": true, "alternativeRecommended": true },
  "altTextDraft": "공연 포스터. 봄의 제전. 11월 8일 토요일 저녁 7시 30분, ...",
  "results": [
    { "layerId": 6, "text": "11.8(토) 19:30", "role": "date", "purpose": "info", "purposeSource": "suggested",
      "check": "contrast", "status": "fail", "statusLabel": "실패",
      "metric": "대비 3.2:1 · 기준 4.5:1 · 단순한 배경",
      "fix": { "type": "color", "value": "#6F6A5E", "strategy": "full", "passes": true, "contrastAfter": 4.67 } },
    { "layerId": 5, "check": "contrast", "status": "conflict", "statusLabel": "충돌",
      "fix": { "type": "color", "value": "#FFFEFD", "strategy": "minimal", "passes": false },
      "alternative": { "type": "altText", "draft": "공연 포스터. 봄의 제전. ..." } }
  ]
}
```

| `status` | 뜻 |
| --- | --- |
| `pass` 통과 | 기준을 넘어요 |
| `warn` 주의 | 조금 모자라요 |
| `fail` 실패 | 정보 글자가 기준에 못 미쳐요 |
| `advisory` 참고 | 예술 글자가 기준에 못 미쳐요 (디자이너 판단 존중) |
| `conflict` 충돌 | 복합 목적에서 그림을 가리지 않고는 고칠 수 없어요 → 대체 정보 |

`fix.passes: false`는 "가장 나은 수정이지만 기준에는 못 미친다"는 뜻이에요. 키우면 다른 글자와 겹치거나 포스터 밖으로 나가는 크기 수정(`fix.layoutWarning`)도 `toApplyFixes`가 기본으로 빼요 (`includeLayoutConflicts`로 넣을 수 있어요). 디자이너가 위치를 옮긴 뒤 켜는 게 맞아서예요. `toApplyFixes`는 이런 수정과 예술 '참고' 수정을 기본으로 빼요 (`includeFailing`, `includeAdvisory` 옵션으로 넣을 수 있어요).
